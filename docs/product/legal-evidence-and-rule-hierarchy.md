# 规则依据层级：法律、司法裁判、行政规章与学校制度

> **状态：2026-10-21 · 产品治理原则 / Discovery。** 本文为 ClassMatter 后续开展风险协同业务分析的通用证据方法，不是法律意见、心理危机诊断指南或当前 R1 具备的规则引擎。本文不包含真实教师、学生、学校或访谈材料。所有引入正式工作流的规范必须在采用时重新核对官方有效文本、学校实际制度和适用人员。

## 1. 先找有权依据，再决定产品如何做

任何涉及学生安全、心理健康、班主任履职、家校沟通、校园欺凌、住宿或事故处置的产品规则，**不得从 AI 的常识、个人经验、某个案例的赔偿结果或学校传闻直接推导**。

推荐研究步骤：

1. **确定法律事实框架**：行为发生时间、地点、学生民事行为能力、在校/寄宿/校外活动、当时谁获知了什么、班主任/值班人员/校方的实际授权、是否存在即时危险。
2. **先核对官方规范原文**：适用法律、行政法规、地方性法规、部门/地方政府规章、有效规范性文件；记录制定机关、条款、地域、时间和修订状态。
3. **独立检索司法解释和案例**：核验是否为最高法指导性案例、已生效其他案件、典型案例，或者仅为尚未生效的一审报道；对比事实和争议焦点。
4. **再核对学校实际流程**：经批准的职责分工、值班制度、报告渠道、心理危机/欺凌/伤害事件预案，以及接收确认的形式和责任；不将学校内部制度凌驾上位法。
5. **输出有限的业务规则候选**：触发信息、必须/可以/建议动作、谁有权限、由谁复核、送达和交接如何确认、什么情况下停止自动建议。法条有争议或校规未确认时，显示“待核验”而非虚构强制义务。
6. **用合成负例审查**：未送达、未接手、老师不在场、无法合理预见、事后补录、误关联学生、系统停机、需要先救助的危机；保留旧版本以供复盘。

**履职与留档是两回事**：证据有助于重建真实的工作过程，但不能自动证明已经依法尽责；缺少电子记录也不当然等于失职。严重结果不能自动倒推教师必然知情或承担全部责任。

## 2. 规范效力：不能把所有依据硬排成一条单向列表

以官方 [《中华人民共和国立法法》（2023年修正）](https://hubca.miit.gov.cn/zwgk/zcwj/flfg/art/2023/art_617433c825534c34a1104d67a6254ba2.html) 第98—107条为原则：

| 类型 | 设计时怎么用 | 限制 |
|---|---|---|
| 宪法、法律 | 国家基本权利义务与责任归属的首要规范依据；学校场景常涉《民法典》《未成年人保护法》《教育法》 | 不能将概括性原则冒充操作清单 |
| 行政法规 | 国务院制定的适用规则，效力低于法律、高于地方性法规和规章 | 确认法规版本及适用对象 |
| 地方性法规 | 湖南省人大及其常委会制定的适用法规可约束本省学校 | 与部门规章的冲突**不一定能机械按高低判断**，依法定程序处理 |
| 部门规章 / 地方政府规章 | 如教育部令《学生伤害事故处理办法》，核对权限、地域和版本 | 部门规章与地方政府规章各有权限；按《立法法》第102、106条处理争议 |
| 行政规范性文件及政策 | 省市县教育机关发布的正式工作细则，需核对有效性、制定权限和上位依据 | 不是当然与法律、行政法规、规章同级 |
| 学校校规、岗位职责及应急预案 | 将法定义务与管理要求落到现场谁接电话、何时报送、谁值班等 | 必须合法有效并获校方正式确认，不能单凭系统界面转移责任 |
| 行业指南、专家意见、产品假设 | 作为可选择的设计和评测输入 | 不能自动标为“依法必须” |

还必须核对特别法与一般法、新旧法和不溯及既往等规则；当不同制定机关的规范发生冲突时，依据《立法法》的法定处理路径复核，不由 Agent 宣布哪个规范“失效”。

### 司法解释与案例单独记录，不混同法律位阶

- **司法解释**：依法作出的司法解释应作为法律适用的重要依据独立核对生效版本；不能等同普通新闻解释。
- **最高法指导性案例**：最高法 [《关于统一法律适用加强类案检索的指导意见（试行）》](https://www.court.gov.cn/fabu/xiangqing/243981.html) 第9条规定，符合条件时人民法院**应当参照**；如与新的法律、行政法规、司法解释冲突或已被新指导性案例取代，则不适用。
- **其他生效裁判、典型案例**：用于事实与法律争点的类案比较，通常是**参考**，不是全国学校必须复制的固定规则。
- **报道中的一审判决**：需要查明是否已生效、是否有二审改判和裁判全文；不可将“学校赔偿多少”转化为“班主任个人赔偿多少”。

案例库必须记载法院、案号、裁判日期、生效性、相似/不同事实、主要争点、依据法条与使用限度。特别警惕“有疏导但未采取必要升级措施”和“确无可预见线索”这两类事实完全不同的情形。

## 3. 首批官方原文：适用于湖南初中情境的候选证据

下表是**需求研究起点**，不是穷尽清单；实际使用时需检索更近版本、相关司法解释和专业制度，不能以本文件代替合规审查。

| 官方文件及条款 | 影响的业务设计问题 |
|---|---|
| [《民法典》第1191条、第1199—1201条](https://fjca.miit.gov.cn/zwgk/zcwj/wjfb/art/2020/art_9f0ef44677164c5eb3a5585bf82a07cb.html) | 单位责任与存在故意/重大过失时向工作人员追偿的区别；学校在不同民事行为能力情境下的教育管理责任 |
| [《湖南省学校学生人身伤害事故预防和处理条例》第3、4、45、47条](https://jyt.hunan.gov.cn/sjyt/xxgk/zcfg/flfg/201807/t20180726_5061643.html) | 各司其职；责任与可预见性；第45条免责情形仍以学校确已尽责、无不当行为为前提；第47条涵盖寄宿住宿期间 |
| [《湖南省促进学生心理健康条例》第5、6、11、20条](https://www.hnrd.gov.cn/content/646949/63/15001764.html) | 家庭、学校、班主任与专业人员各自职责；校内心理健康协同、严重问题的专业转介/监护人告知与心理信息保密 |
| [教育部令第12号《学生伤害事故处理办法》](https://www.moe.gov.cn/srcsite/A02/s5911/moe_621/200206/t20020625_81855.html) | 事故适用范围、学校安全制度、救助要求、监护责任与相关认责要件 |
| [教育部令第49号《中小学教育惩戒规则（试行）》](https://www.moe.gov.cn/jyb_xxgk/xxgk/zhengce/guizhang/202112/t20211206_584996.html) | 处理冲突和违纪时，惩戒权限、程序和禁止行为，不能由产品擅自定性与处分 |

特别说明：心理健康条例第11条规定了**学校**建立分级预警和干预机制的责任，不得直接推成班主任个人可以或必须进行医学诊断。第20条涉及高度敏感信息保密，现有 R1 禁止 D4 心理、健康等资料，不得以所谓“依法留痕”为由偷偷扩大采集范围。

## 4. Rule provenance：从来源到工作流的一条证据链

未来每条制度性规则候选至少登记以下字段（**设计草案，非当前数据库/API**）：

```yaml
rule_id: RULE-EXAMPLE-NON-R1
scenario: CASE-SAFE-03
jurisdiction: 湖南省/具体学校待确认
actor_and_scope: 班主任、值班人员、学校主管人员
source_title: 规范正式名称
source_type: 法律/法规/规章/政策/学校制度
issuing_body: 制定机关
official_url: 原文链接
article_or_section: 具体条款
effective_from: YYYY-MM-DD
effective_to: null
version_checked_at: YYYY-MM-DD
interpretation_or_conflict: 待人工复核
case_refs: []  # 案例需独立标记生效性、相似度及参考限度
school_approved: false
decision_authority: 指定合规与校方人员
implementation_state: discovery_only
allowed: 提示核对正式预案与有权人员
prohibited: 自动诊断、自动法责判断、自动免责
```

**政策来源、事实证据、组织授权、工作状态四种权威绝不能互相代替。** AI 生成的风险解释属于 Draft，不得自动变为学生心理诊断、法定义务、处分决定或业务数据库正式事实。来源版本过期、链接无法验证、法规被修订、学校制度变化时，应暂停自动化规则并交人工审查。

## 5. 四个真实问题原型如何审查（均为虚构情境）

1. **谈话后在老师不在场时出事**：复核当时已知事实、明确风险信号、措施、升级、交接、事后新增信息。不能只看是否有谈话记录，更不能由结果自动认定失职。
2. **老师事前并不知道心理问题**：严格区分真的没有信息、未保存信息、应当合理知道的信息；参照湖南学生伤害事故条例第45条的具体前提审查，不以“未知”直接判免责，也不事后补写成早已知情。
3. **明确自伤意图而只做日常安慰**：按学校正式危机预案与适用地方条例要求审查当场安全、报告、专业干预、监护人告知及责任分工。紧急处置优先，不能先让 AI 生成风险分再救助。
4. **寄宿生夜间失联或受伤**：住宿期内学校安全管理职责存在；班主任、宿管、值班人及校方的具体任务须看法定规则与有效校内制度，不能把“收到了消息”假定为“我已经承担全部责任”。

## 6. 进入产品前的硬性审查门

以下任一出现时，该规则停留在 Discovery，不允许以“已上线安全工作流”对外宣称：

- 缺失可追溯官方规范原文、条款、有效版本、地域、场景或适用主体；
- 只找到新闻/未生效一审案例，却将其当作普遍法律要求；
- 法规、部门规章、校规的关系或冲突未经人工处理；
- 把“鼓励/建议/可以”改写成强制义务；
- 真实学校未确认值班职责、上报对象、接收确认或应急替代路线；
- 通过 AI 自动判断心理疾病、法律过错、损害赔偿额或组织责任转移；
- 收集、共享、导出或向外部模型发送未授权学生敏感信息；
- 让软件页面或记录动作阻碍即时线下救助；
- 隐藏事后补录时间、覆盖原始记录，或者把无回执写为“已接收”。

进入任何 Future release 必须完成学校制度审查、合法数据处理条件、隐私与安全评测、专业审核、合成与真实任务净负担验证和正式版本 Gate。**新增本文件本身不修改 R1 manifest、107 项规格需求、Eval、Task 或机器 Gate。**

**维护责任**：规范来源由法务/合规人员核对；学校流程由授权校方确认；教学与心理专业问题交由专业人员；系统工程由开发团队实现可审计的技术边界。法规修订、案例取代、校规调整、岗位变化时触发复核，不把旧来源当作永久真理。
