## 0. 产品主张：让系统适应老师，而不是让老师持续适应系统

ClassMatter 是 External Working Memory + Closure Engine。除管理班级的事实、任务、跟进与证据外，长期可研究如何在合法授权和边界内逐渐适配教师的个人工作方式：表达风格、工作习惯、历史经验及人机分工偏好。目标是减少重复交代、反复修改、错误打扰和无效操作，不是模仿人格、替代教师职业判断或扩展组织授权。

**待验证假设**：在不增加有害错误、隐私风险及持续维护成本的前提下，具有可控、可撤销个人工作偏好的 AI，能降低同类班务的端到端净耗时和人工修改次数；未经真实使用验证，不声称一定减负。

## 1. 四类工作画像，而非单一 Persona

| 领域 | 典型样例（均为虚构） | 需要防止的误用 |
|---|---|---|
| Expression / 表达偏好 | 给家长的日常沟通偏简洁、先事实后安排；给学校的汇报需明确日期和依据 | 某一次严肃口吻被误认为长期偏好；过度模拟人格 |
| Workflow / 工作习惯 | 放学前集中处理普通回复；重要待跟进事项习惯先查看来源再决定下一步 | 将个人习惯上升为学校法定义务或绕过规定时限 |
| Experience / 工作经验 | 某类沟通先给出可选择的时间段可减少反复；可被证据支持或证伪 | 一次成功被当成通用真理、把个案学生情况写进通用规则 |
| Delegation / AI 协作偏好 | 一般性草稿可预填；外发、敏感记录和正式状态变更必须老师确认 | 偏好被当作正式权限授权，造成越权执行 |

与业务资料严格隔离：Teacher Working Profile 不得成为学生人格/风险画像，不得把家长个人信息、病情、学生心理、纪律材料固化成泛化工作偏好。老师换班级/学校后，个人偏好也不能自动带走原班级域内的受限事实。

## 2. 信息类型与信任边界

- **Domain Fact**：来源、时间、版本、授权明确的正式班级事实；由领域服务持有，Memory 无权改写。
- **Working State**：任务当前处于 Ready/Waiting/Review/Done 等什么阶段，如何验证闭环；由业务服务持有。
- **Knowledge/Policy**：法律、正式校规、学校程序、教育专业指引等；须区分有效性、适用地域与来源，不能被个人偏好覆盖。
- **Preference Memory**：教师确认的可撤销工作偏好，必须携带适用任务/受众/场景范围与版本。
- **Behavioral Signal**：教师对草稿的修改、拒绝、使用、提醒反馈等候选信号；不等于教师授权保留记忆，不等于正确规则。
- **Procedural Experience**：经脱敏、审核和评测形成的可重用处理经验/策略候选；不是法规，也不自动跨教师共享。
- **Conversation/Runtime Context**：当次模型工作的临时上下文；压缩会话不是业务状态，也不是业务权限。

冲突优先级候选：**上位有效规则与正式权限/业务事实 > 本次教师明确要求（仅合法权限内） > 教师已确认且适用于当前场景的偏好 > 本次临时推断/候选行为信号**。规则发生冲突、来源不明或重要业务结论不确定时应显示冲突/要求确认，不凭该排序强行给出结论。

## 3. 两个不同的学习回路

### A. 偏好适应：面向当前教师

1. 使用教师明确设定的偏好，或在知情可控的前提下记录最低必要的修改/采纳反馈。
2. 在同一任务类型和受众范围内观察重复模式；不因一次修改推断永久偏好。
3. 提炼「候选偏好」：内容、适用范围、证据摘要、置信与不确定性、版本、保存期限。
4. 通过简洁、可跳过的教师确认界面提升为 Preference Memory；老师可编辑、暂停或删除。
5. 在后续相似任务中按需检索、应用，并允许单次覆盖。
6. 当教师否决、偏好过期、角色/学校变化或来源撤回时，禁止继续当作有效偏好使用；相关缓存/派生索引同步失效。

**待讨论**：无须每次都确认的「只在当前会话临时适配」与「跨会话长期记住」必须分开；若要求教师频繁批准偏好反而增负，就应减少学习频率或回退至简单的显式设置。

### B. Agent 自我改进：面向执行策略

1. 记录最小化、去标识的任务目标、工具轨迹、版本化输入、失败分类与结果。
2. 用业务级 Eval 判断是否真的改善任务质量、工作净耗时、安全性和成本。
3. 形成 Prompt/Context 选择/工具顺序/提示建议等**离线改进候选**。
4. 在冻结基准和独立保留集上比较，经过必要人工审查再发布为新版本，失败可回滚。

这里的 RSI 指 **受控的应用层自我改进**，而不是让线上模型擅自修改业务规则、权限、数据库 Schema、生产代码或学校制度。教师偏好学习与系统级性能改进必须各自隔离：不能把一位教师的私人行为直接提升成默认系统策略。

## 4. 偏好记忆的最小概念合同（非数据库设计）

候选字段：profile_owner_ref、workspace/scope、task_type、audience、preference_kind、content_or_rule、source_kind、source_refs（最小化/可撤销）、evidence_summary、status(candidate/confirmed/rejected/superseded/expired)、version、effective_from、expires_at、supersedes_ref、consent_basis、updated_at、invalidation_links。

注意：
- Confidence 是启发式线索，不是真实偏好的正确概率。
- 同一句话对家长、学生、领导可能有不同风格，不能一份全局 Prompt 通吃。
- 允许「没有偏好」「仅本次有效」「临时暂停」，拒绝也应被尊重。
- 不默认保存消息全文、通讯录、心理/健康敏感事实作为训练材料；仅保留有必要、经授权的最小证据。
- 任何派生记忆在来源更正、撤销或权限变化后需要显式失效，不应只删除列表可见项。
- 日志、备份、导出和跨设备同步也在保留/删除/隐私治理范围内，需要单独明确保留政策和恢复边界。

## 5. 三个候选交互旅程

**EX-01 家校沟通草稿**：教师多次将「感谢您的配合」改为更简洁的事实陈述。系统先在当次草稿内响应；经多次、同场景、可解释的反馈，提出一张低打扰卡片：「给家长的日常消息偏直接、简洁，今后采用此风格？」教师可接受、编辑、仅本次使用或忽略。后续可用「为什么这么写」查到偏好来源。正式外发仍须通过对应授权与人工确认。

**WF-01 午后班务整理**：教师习惯将非紧急待办集中到固定时段查看。系统形成候选提醒偏好；仅在不影响必须及时处理的事项、学校时限和法定职责时适配 Attention。紧急事项、逾期上报不能因个人习惯延后。

**XP-01 经验再利用**：一项普通班务反复缺少回执。系统在合成样例中学习「发出通知≠确认收到」，调整未来任务草稿中的状态区分和跟进提示。它是已有领域不变量的再利用，不是自动推定法律责任，也不能凭经验宣称某个学生或家长存在特定问题。

## 6. 与 ClassMatter 现有架构的关系

- 继续保留 Query Gateway / Business Command Gateway / Identity Security Boundary 的受控边界；Agent 只读/草稿现状不变。
- Teacher Profile、Memory Candidate、Observation Feedback、Improvement Proposal 是**概念角色**，非立刻新增领域对象、万能 Memory 表或外部向量数据库的指令。
- 优先把首个实验绑定现有「查询/草稿」链路，复用合成业务 fixtures 与 Eval Runner，不扩展真实学生数据处理。
- Pydantic AI 仍可作为默认 Runtime。框架的 Conversation、Memory、Persistence 能帮助运行，但应用必须自己承担来源、权限、版本、撤销、冲突解决；换 Pi 不是前置条件。
- 在当前 R1 冻结范围内不新增能力；进入后续版本须先明确需求/案例/ADR/工具/安全/评测/任务/发布门，不能借本研究文档提升状态。

## 7. Eval：同时证明『更像老师』和『不越界』

最小候选对照：无画像 vs 显式偏好 vs 经确认的适应画像；同模型、相同班务输入、相同工具权限、相同总预算。

- **实用价值**：教师完成同类消息的总耗时、手动修改次数/幅度、一次采纳率、偏好设置与审核负担、提醒打断次数、净耗时。
- **正确性与质量**：事实遗漏/虚构、受众适配、语气与表达匹配、学校规范符合度、任务/对象关联正确性；避免仅用文字相似度代表质量。
- **长期可靠性**：旧偏好被新版替代后是否还被错误召回；仅本次例外会否污染全局；换班/换校后是否泄露隔离信息；撤销/删除后派生数据是否失效。
- **安全硬门槛**：越权读取/写入、未经授权外发、敏感信息跨主体泄露、风险处置被偏好覆盖、错误事实被当成经验固化，均不得以平均效率收益抵消。

测试先用虚构教师、虚构家长和合成任务；实际用户研究需要独立的授权、最小化数据和适当的审批。研究人员不以「复制用户风格成功」冒充教育业务有效性。

## 8. 技术研究参考（不是引入依赖的决定）

- Pydantic AI Persistence / Memory 官方文档区分 Conversation、StepPersistence、跨会话 Memory、Durable Execution；其记忆笔记模型本身并不天然携带已验证来源，需要由应用补齐：[Persistence](https://pydantic.dev/docs/ai/core-concepts/persistence/) · [Memory](https://pydantic.dev/docs/ai/harness/memory/)。
- 2025 EMNLP 关于隐性写作风格模仿的研究提醒：少量示例能帮助结构化邮件，但对细微、非正式风格的复制能力有限，须实际评测：[ACL Anthology](https://aclanthology.org/2025.findings-emnlp.532/)。
- 2026 年关于可信记忆合并和幽灵旧记忆的研究指出：错误提炼、旧记忆残留和更新时的扭曲会在跨会话持续扩散，因此写入侧和检索侧都需要测试：[TrustMem](https://arxiv.org/abs/2606.25161) · [A-TMA](https://arxiv.org/abs/2607.01935)。

以上外部研究是风险与设计方向参考；与本项目可行性之间仍需自身实验。

## 9. 下一轮讨论优先解开的六个问题

1. **默认学习多主动？** 完全显式设置；教师同意后自动发现候选、确认后持久化；还是先仅在当前会话调整？目前倾向第二种，但须验证审核负担。
2. **表达偏好要做到多细？** 用户 × 受众 × 任务类型 × 情境的组合，怎样避免长尾稀疏、过拟合和维护成本？
3. **什么样的修改是真偏好？** 单次编辑、纠正事实、临时情绪、法规要求、口吻选择如何区分？如何反证？
4. **老师跨班级/学校换岗时能带走什么？** 仅个人确认偏好可申请迁移，相关班级受限数据与组织权限绝不自动随身。
5. **长期行为反馈保存多久？** 默认不长期保存原始消息，需设计最小化事件、聚合与有限保留期；删除、备份、导出需闭环。
6. **真正值得优先测试的单一场景？** 建议先选「低敏家校沟通草稿的个人表达偏好」，不加入真实外发、敏感学生个案或自动任务写入。

## 10. 决策状态

- **已确认的方向**：个性化 AI 协作值得作为长期研究方向；不能混同正式业务事实、授权、学校规章或未成年人的敏感画像。
- **尚未确认**：用户是否愿意开启行为学习、必要的同意和留存范围、UI 形式、领域数据模型、技术框架/检索方法、Eval 阈值、正式版本规划。
- **下一步**：继续围绕场景、被动学习的边界、偏好类型与最小可测原型开展产品讨论；不创建实施任务或重排 R1。
