# 学生安全与履职协同：异常事件、证据链与组织交接

> **文档状态：Discovery / Future 场景规范（2026-10-21）。** 本文提供供学校共同评审的业务设计，不提供心理诊断、法律意见、即时风险预测或事故免责保证；不是 R1 功能、不是已上线流程。全部案例为合成、无身份信息。**真实学生的健康、心理、处分等 D4 资料禁止进入现有 R1。**

## 0. 设计命题与边界

需要区分三个问题：

1. **真实义务与可合理预见性**：事故结果严重，并不能倒推出某个教师事前必然知道、一定失职。履职标准、实际信息、岗位职责、处置行为和因果关系，需由学校及有权机构依具体事实认定。
2. **履职与证据是两件事**：做了事但没有记录，事后可能很难还原；有记录却没有实际行动，更不能构成尽责。记录是“可核验的过程材料”，不是自动免责凭据，也不能自动转移责任。
3. **班主任是组织中的一环**：学校负责人、年级/德育、专职心理教师、校医、宿管和值班人员均可能有独立职责。消息发出不等于收到，收到不等于正式接手，接手不等于事情已经完成。

因此产品不是“消解一切异常”，而是帮助**及时识别已有可信线索、依制度响应、降低交接断裂与遗漏，并在必要时复盘**。风险本身不可能被消灭。

## 1. 业务状态机（未来拟议，而非现有 API）

```text
线索捕获/教师发现
       ↓ （先判断是否需要立即线下响应）
事实/观察/主张分层，核对人、来源与时间
       ↓
按学校正式预案分流：日常关怀 / 需上报 / 紧急处置
       ↓
实际措施 + 记录（救助优先，记录可事后补）
       ↓
指定渠道上报 / 监护人沟通 / 专业人员转介
       ↓
送达状态 → 接收确认 → 明确后续负责人
       ↓
跟进 / 等待 / 再次升级 / 持续观察
       ↓
按正式处置结论关闭或重新开启 + 可追溯证据
```

### 状态必须精确定义

| 状态 | 能声明什么 | 不能冒充什么 |
|---|---|---|
| draft | 尚未确认的录入或 AI 草稿 | 正式事实、已上报 |
| recorded | 经授权保存的观察/事件 | 已处置、已诊断 |
| action_taken | 指定措施在某时被实际执行并由记录者确认 | 校方批准或措施必然有效 |
| report_requested | 准备或尝试发送报告 | 送达成功 |
| delivered | 已通过可信渠道获得送达证据 | 接收人已经确认负责 |
| acknowledged | 指定接收人已确认收到 | 已接受正式委派、已执行 |
| responsibility_accepted | 依制度和权限被正式接收的任务 | 原责任自动完全消失 |
| monitoring / followup_due | 需要观察/复访，给出责任人与下次时点 | 已结案 |
| resolved / transferred / cancelled | 按有权流程结案、交接或撤销并给出依据 | 从历史中删除 |
| reopened | 新事实使原结论需要再评价 | 自动判定历史人员过错 |

所有正式状态变更必须有授权范围、版本、时间、操作者和不可伪造的系统收据；不同渠道没有核验成功回执时只能显示“人工标记/待核实”，不能宣称组织接受。

## 2. 四类关键案例与应答边界

### CASE-SAFE-01：一般情绪困扰，谈话后在老师不在场时出事

**示例**：某学生表达学习压力，班主任正常谈话、给予支持；没有明确急迫危险信号，之后在别处发生严重意外。

产品应显示当时实际可得的信息、谈话时间、措施以及后来新增的信息；不要在事故后逆向给先前谈话自动补“高危”，也不要推定“老师肯定应当预见”。若当时已有升级信号，则必须据事实检视是否依制度报告与转介。

### CASE-SAFE-02：从未获知诊断，也没有合理可见的线索

**示例**：监护人未告知、学生未显露明显异常、教师没有得到其他提示，事后出现突发事件。

系统不得基于事后结果推断教师此前“知情”；无记录不证明事实不存在，所有不确定项标记 Unknown，收集客观独立证据，不做责任结论。不得通过秘密监控或未经授权筛查来试图让教师“全知”。

### CASE-SAFE-03：明确表达紧迫自伤风险

**示例**：学生明确表达近期伤害自身的意图，或正在发生危险。

**优先顺序**：立即按学校应急预案采取保护措施、联系现场有职责的成人/应急部门/专业人员，并按制度通知监护人；不得让学生仅等待软件审核或生成文字。软件故障、断网、账号无法登录时依然必须执行线下路径。后补录发生时间、获知时间、第一实际处置时间、上报对象和接收确认；需要敏感数据权限和学校明确授权后才能开发。

### CASE-SAFE-04：寄宿生夜间失联、冲突或受伤

学校已有值班、宿舍、出入校、请销假和应急制度通常涉及多个角色。不能把班主任“被通知”自动当作“全程监管责任人”；应从制度中明确夜间当值人员、协同方、应急电话和最小必要信息。任何新增组织角色必须经过身份授权和最小披露设计。

## 3. 未来可讨论的结构化记录（不是 R1 表结构）

```text
case_id（非持久 R1）/ subject_ref / authorized_scope
observed_at / occurred_at / learned_at / recorded_at
source_type / source_reference / epistemic_type
objective_summary / uncertainty / confidentiality_level
action_type / action_time / action_actor / result
report_channel / recipient_role / sent_at / delivery_evidence
acknowledged_at / accepted_scope / next_action / next_owner
followup_at / case_status / closure_reason / version / audit_ref
```

**录入原则**：只收集达到处理目的所需的最少字段；个人微信聊天全文、病历、录音和心理诊断不应成为默认必填项。涉及未成年人的心理、健康和家庭隐私时须有合法依据、专门授权、访问审计和清晰保留/删除规则；原则上由学校批准的渠道与环境保存，不上传私人云盘或未授权的外部 LLM。若学校已有权威系统，优先使用其流程而非另造一份相互矛盾的“第二档案”。

## 4. 异常分流应如何设计

- **日常一般事务**：允许简单事实/观察和个人跟进；不进行心理健康“打分”、群体排名。
- **需要学校协同**：依据学校正式预案触发人工上报和指定角色接手；显示“未确认”“待重试”；人员缺席时有人工替代升级方案。
- **现实紧迫危险**：清晰提示立即线下救助与通知责任人员；不要求先登录、填表或等待 AI；产品提醒不能替代报警或急救。
- **信息不足/身份不明**：澄清对象和来源，不伪造确定性、不误关联同名学生、不向错误监护人发送。
- **证据冲突**：保留原始版本与更正来源，事实/自述/观察分区；不无痕覆盖、不反向篡改事件时间。

## 5. 最值得防范的失败模式

| 失败模式 | 为什么危险 | 必须有的护栏（未来版本） |
|---|---|---|
| 记录了“已上报”但消息没送达 | 危机可能无人知道 | 必须区分草稿、发送尝试、送达和接收 |
| 班主任一键“转交”，对方未确认 | 形成交接空档 | 等待/升级可见，不声称已移交责任 |
| AI 从成绩或聊天推断“心理疾病” | 错误标签及隐私歧视 | 禁止诊断/永久标签，AI 推断不进正式事实 |
| 误把学生 A 的记录挂到学生 B | 泄漏信息并干扰判断 | 身份匹配确认、错人回滚与派生失效 |
| 本来应先救助，界面强制先填字段 | 延误救助 | 紧急操作不被软件阻挡，事后补记录 |
| 断网/模型故障没有替代流程 | 错失时机 | 线下预案优先、软件不承担应急指挥依赖 |
| 事后补录不显示补录时间 | 篡改嫌疑，历史误导 | 区分发生/获知/记录/更正时间与审计 |
| 任意人可看心理/家校材料 | 未成年人隐私泄露 | 最小权限、用途限制、访问审计、保留期限 |
| 自动提醒过多或漏提醒 | 注意力疲劳、误信 | 预注册指标评估，允许暂停，不承诺绝不遗漏 |
| “系统记录”被说成“法律免责” | 误导老师和校方 | 对外始终声明法律归责需个案认定 |

## 6. 与学校真实制度的对齐门

试点前必须与校方合规/管理人员核对，而不是由开发者凭常识定义责任矩阵：

1. 班主任、年级组长、德育、心理教师、校医、宿管、值班与校领导各自职责、替班与离岗规则。
2. 校方正式的心理危机处置、反欺凌、突发疾病、安全事故、请销假、住宿与信息报告预案。
3. 事件分级、必须通知的对象、渠道、时限、夜间路径与经授权的紧急替代方案。
4. 监护人联系方式及敏感资料的合法获取、最小披露、保存、共享、导出与销毁要求。
5. 系统产生的记录在校方既有业务流程中的效力，以及对方如何真实确认接收。

未完成上述审核，不提供“学校正式事故留痕系统”“心理风险识别/预警系统”等产品承诺。

## 7. 合成验收脚本与反证指标

| 测试 ID | 给定 | 期待结果 |
|---|---|---|
| AT-SAFE-01 | 教师完成一般谈话，后续跟进已到期 | 正确出现 Open Loop；当前 R1 仅在非 D4 事实范围内验证手工任务 |
| AT-SAFE-02 | 上报发送失败或没有回执 | 不显示“已告知/已接受”；显示需要采取线下替代措施 |
| AT-SAFE-03 | 明确紧急危险、系统恰好离线 | 不依赖系统才能执行救助；事后记录显式迟记 |
| AT-SAFE-04 | 事故发生前没有预警记录 | “未知/无可用证据”，不擅自判失职或判免责 |
| AT-SAFE-05 | AI 推断与教师观察互相矛盾 | 不把推断升为正式诊断或自动优先任务 |
| AT-SAFE-06 | 班主任将任务转给宿管但无人确认 | 仍显示未完成交接，不自动改变组织责任 |
| AT-SAFE-07 | 同名学生、错误监护人 | 拒绝自动发送，先澄清身份及授权 |
| AT-SAFE-08 | 事故后试图回填更早“已汇报” | 系统保留真实系统记录时间与修改审计，拒绝无痕改写 |
| AT-SAFE-09 | 非授权账号查询敏感案例 | 拒绝访问、最小错误披露、可审计 |
| AT-SAFE-10 | 短期任务更快，但老师需要额外记录两倍时间 | 失败：不满足 Net Burden，需简化或停止 |

评估指标包括：准确上报和交接率、错误关联率、迟记可见性、无效/重复提醒率、复访遗漏率、找回处理证据的耗时、每周净维护分钟数、权限与敏感信息事故数、教师对责任压力的变化。**安全、隐私、错人、延误救助和误导责任判断是独立硬门，不能用节约工时抵消。** 使用前预注册阈值和失败处置，不编造量化效果。

## 8. 交付阶段建议与现有版本的关系

- **R1：不得扩容。** 先演练已有非敏感 Record → Task → Today / Timeline，验证老师能否正确回看事实和跟进结果；相关测试使用虚构学生。
- **Discovery：** 与至少五位背景不同的目标班主任及有权限的学校管理人员做流程走查，基于匿名、授权的制度材料验证“谁报告给谁”。访谈不能未经授权引用个人原话或保留学生细节。
- **未来独立切片 A：** 在许可范围内验证家校沟通的草稿、人工确认与状态追踪；不自动外发。
- **未来独立切片 B：** 建立学校授权的 Case/Handoff/Acknowledgement 与多角色最小披露；不把接收通知等于承担法律责任。
- **未来独立切片 C：** 若有明确合法数据基础、专业共建与安全审查，才讨论高度敏感的心理危机协同；AI 仅辅助流程检查与文书草拟，不能独立分诊或代替线下预案。

任何切片启用都必须创建新的 release applicability、业务规则、数据保护设计、评测、任务和正式准入证明，不能因为本文描述场景就修改现有 R1 的 107 条需求或 machine Gate。

## 9. 公共表述建议

> ClassMatter 探索把班主任的零散事务转化为可追溯的事实、任务和跟进链路。更长期的方向是帮助学校及教师在真实职责和权限边界内进行事件跟进、异常信息协同与过程复盘。它不保证预测事故，也不取代学校的应急处置、专业心理服务或法律责任判断。
