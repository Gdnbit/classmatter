# Personal Agent：持续委托的小结闭环

> 2026-11-14，实施设计与本地工程验收。基线 main 93079f1；独立[PR #105](https://github.com/Gdnbit/classmatter/pull/105)记录精确head CI、真实免费模型逐次结果和最终合并状态；研究补正见[Personal Agent 研究](../research/2026-11-14-proactive-agent-clarification-and-followup.md)。仅合成开发，不改变冻结 R1、正式 Requirement/Eval/Task/Gate、生产数据或 Agent 业务写权限。

首个窄场景的实际SDK/PG/HTTP/原Web工程闭环及一次含重试的既有免费Gemini完整演练已通过；后者240.98秒、两份文档及摘要版本2回读一致。503/504、模型内容拒绝和初始化失败分别保留，不据此声称稳定性SLA或通用Personal Agent全部交付。最终head自动检查与合并状态以PR为准。

## 目标与范围

老师在原聊天明确委托持续积累本班小结材料，沿现有预览确认一次；之后只记录事实和处理任务，系统根据真实新增材料自主判断是否值得准备小结，有关键缺项才提问，并从明确长期反馈调整后续格式。没有变化、没有委托或委托暂停时保持安静。用户不需要重新发起每一次小结，也不新增配置页面或表单。

## 复用与存储决策

- 委托使用现有工作文档的固定可读格式，仅覆盖“班级工作小结”一个程序，含启停、格式和明确要求核对的材料；通过窄类型解析及既有 document.create/revise → preview → human confirm → BCG 保存。它是用户可编辑的工作指令，不能替代正式事实或法律/组织权限。
- 新增固定的 personal_summary_attempt 关系，绑定委托修订、材料摘要、原聊天/消息与待答状态；不新增万能目标、Memory 或 Workflow 表。
- 主动消息由受信应用编排产生，以来源关系标识；不伪造用户发言，不开放新的 Agent 业务写工具。正式小结仍是现有 document 候选及真实比较，确认后才成为工作文档。
- 模型、工具、期限/调用次数控制继续复用已锁定 Pydantic AI。周期调度使用稳定 APScheduler，持久执行证据复用原聊天的 claim/generation/lease/finish 与数据库唯一约束。调度器只检查有变化的明确委托，不是通用自动化引擎。
- APScheduler3.11.3的异步调度、同任务并发上限和coalesce行为按[上游3.x指南](https://apscheduler.readthedocs.io/en/3.x/userguide.html)核对；调度条目不序列化凭据，业务耐久性仍由原数据库链提供。
- 本机服务和有效开发会话可用时运行；重启后恢复登记须沿原身份链，不能重放未知/失败的模型调用。离线不承诺准时执行，无变化检查不调用模型。当前不引入常驻云端或新的付费服务。

## 验收

对应研究 PA-01～08、PA-23～28 的首个窄场景，非正式 Eval 状态提升。

- 明确委托可在原聊天准备、预览、确认；刷新/服务重建后仍存在；未确认的委托不执行。
- 不发起“现在写小结”，仅新增合成事实/任务，模型仍可主动准备来源一致的真实草稿；没有事实时不伪造。
- 同一材料只有效生成一次；并发、恢复和重复检查不能重复消息/保存；等待期间不空转模型。
- 缺明确要求的关键材料时提问，回答回到原事项，另一聊天的“是”不能串答。
- 明确“以后用三条要点”可更新长期委托；“这次详细点”不污染长期偏好；暂停后停止主动行为。
- 旧来源变更、委托修订/暂停或聊天清除后，旧执行不能释放新草稿；保留历史原文。
- 原聊天/切页/草稿/确认保存/文档页/刷新保持一致；主动内容不显示成用户发言，不抢焦点。
- 常规测试不调用外部模型；真实免费 Provider 仅显式获准后合成演练。失败及重试单独记录，不冒称首次成功。

## 风险与退出

旧版实例需先创建并验证原修订 checkpoint，再显式迁移；保留原事实、任务、聊天、文档及回执摘要。升级失败保持旧版本或明确拒绝启动，不自动删表降级。停用调度和暂停委托可停止新主动运行，保留历史及原手动聊天。具体可用性以测试及 PR CI 证据为准，本文件不预填“已完成”。

## 实现边界与演练方式

原聊天说“以后持续整理班级工作小结，需要核对班会主题”，核对委托卡后保存；以后只登记普通事实或更新任务。服务按30秒检查实际版本变化，在原聊天准备小结或询问缺失材料，侧栏原对话出现待处理圆点；回复后继续原草稿确认。说“以后用三条要点整理小结”会准备委托修订，“这次详细一点”不改长期格式；“暂停整理班级小结”确认后停止。普通聊天仍无需班级，委托只对明确关联的班级/学期生效。

调度只在本机 API 和已登记有效会话可用时运行；Web 用显式 POST 登记，8秒只读刷新结果，不抢焦点或清除未发送文字。没有新材料、没有已确认委托或已暂停时不调用模型。每位用户24小时最多6次新主动运行，至少间隔1分钟；相同来源失败或未知结果不自动重复派发，原聊天可明确重试。普通事实与任务合计最多100条，超限拒绝生成，不冒充完整历史总结；调度/模型耗时不等于保证准点。

老师答复作为小结中的有署名补充，不自动成为学生事实。当前仅学习明确的长期格式修订，不依据隐含偏好生成个人画像；没有通用目标规划、全天唤醒、通知推送、外部发信、自动安装 Skill、自动更新学校规则或任意记忆写入。

待答问题只是Context，不能覆盖当前意图。老师可先提出其他问题或办理其他事项，必要的政策检索等工具仍可用；无关聊天不消费小结问题。只有明确的小结材料答复/原重试才使用窄工具集合和强制草稿/待答约束，之后返回答复仍可继续原小结。

数据库从0031显式升级到0032；新增表仅保存委托修订、来源摘要、原聊天请求与待答状态，原业务对象和文档保存入口不变。回滚应用须先暂停委托、停止服务并恢复已核验的0031 checkpoint；新版本产生的数据必须先导出保留，不能直接用旧二进制打开0032库或执行删表降级。

等待关系必须绑定实际的`ask_summary_question`调用与消息，不能把模型普通文字提问当作已持久等待。该工具复用SDK顺序屏障，先读当前事实/任务再提问；纯文字“已准备好”也不能代替真实文档候选。主动运行和已确认问题的答复都执行相同约束，模型拒绝使用契约时保留失败，不捏造问题状态。

工程验收使用实际 Pydantic AI FunctionModel 工具循环、隔离 PostgreSQL、真实 HTTP 和原 Web。它证明程序链路，不代表供应商质量。`test_personal_summary_live.py` 仅在显式 `CLASSMATTER_PERSONAL_LIVE=approved-free-only` 时使用已有已激活免费模型，凭据仅经本机保护信封驻内存，不写报告或仓库；逐次失败和成功分别留本机报告，不自动开通付费。
