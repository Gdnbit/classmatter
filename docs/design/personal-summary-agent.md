## 目标与范围

2026-11-15 产品校准：基础班务准备是系统内置任务，不要求老师先发启动语或确认一份委托。当前已关联的有效班级有普通事实或任务、且现有模型可用时，系统检查真实版本变化，准备可核对的班级工作小结；没有新材料保持安静。默认无额外必填材料，不能自行补问班会主题。明确长期反馈、暂停或自定义材料要求才形成可选偏好，仍沿原预览确认；不新增配置页面或表单。准备草稿不代表保存文档、完成任务或接收组织责任。

## 复用与存储决策

- 可选偏好使用现有工作文档的固定可读格式，仅覆盖“班级工作小结”一个任务，含启停、格式和老师明确要求核对的材料；通过窄类型解析及既有 document.create/revise → preview → human confirm → BCG 保存。无既有偏好也能直接准备“以后用三条”或“暂停”的候选；未确认不能改变默认任务。偏好不能替代正式事实或法律/组织权限。
- 保留 personal_summary_attempt 对明确偏好的修订/材料/待答关联；新增固定 builtin_summary_attempt，仅绑定系统任务版本、班级学期、来源摘要与实际聊天请求，运行角色只有SELECT/INSERT。系统默认不是伪造的教师委托或隐藏业务文档，不新增万能目标、Memory、JSON配置或Workflow表。相同班级的已确认偏好（包括暂停）优先，不同时执行两套小结。
- 主动消息由受信应用编排产生，以来源关系标识；不伪造用户发言，不开放新的 Agent 业务写工具。正式小结仍是现有 document 候选及真实比较，确认后才成为工作文档。
- 模型、工具、期限/调用次数控制继续复用已锁定 Pydantic AI。周期调度使用稳定 APScheduler，持久执行证据复用原聊天的 claim/generation/lease/finish 与数据库唯一约束。调度器只检查此内置任务及其明确偏好，不是通用自动化引擎。
- APScheduler3.11.3的异步调度、同任务并发上限和coalesce行为按[上游3.x指南](https://apscheduler.readthedocs.io/en/3.x/userguide.html)核对；调度条目不序列化凭据，业务耐久性仍由原数据库链提供。
- 本机服务和有效开发会话可用时运行；重启后恢复登记须沿原身份链，不能重放未知/失败的模型调用。离线不承诺准时执行，无变化检查不调用模型。当前不引入常驻云端或新的付费服务。

## 验收

对应研究 PA-01～08、PA-23～28 的首个窄场景，非正式 Eval 状态提升。

- 没有委托和启动语时，已有普通事实/任务足以触发内置准备；无材料或无已配置模型时不派发。明确偏好仍须预览确认，未确认不替换默认任务。
- 不发起“现在写小结”，仅新增合成事实/任务，模型仍可主动准备来源一致的真实草稿；没有事实时不伪造。
- 同一材料只有效生成一次；并发、恢复和重复检查不能重复消息/保存；等待期间不空转模型。
- 默认不要求班会主题等额外材料；只有老师已确认的额外要求缺失才提问，回答回到原事项，另一聊天的“是”不能串答。
- 明确“以后用三条要点”可更新长期委托；“这次详细点”不污染长期偏好；暂停后停止主动行为。
- 旧来源变更、委托修订/暂停或聊天清除后，旧执行不能释放新草稿；保留历史原文。
- 原聊天/切页/草稿/确认保存/文档页/刷新保持一致；主动内容不显示成用户发言，不抢焦点。
- 常规测试不调用外部模型；真实免费 Provider 仅显式获准后合成演练。失败及重试单独记录，不冒称首次成功。

## 风险与退出

原聊天列表的待处理标记须有独立宽度，长标题在自身区域省略，不能将标记挤掉；它只提示原对话有待答小结，不自动切换或占用其他对话的输入。切换时移除上一对话的临时“已保存”提示，实际历史比较和回执仍绑定原消息。未发送文字的承诺范围仍是当前应用会话内的切页/切对话，不提升为刷新或进程重启后的草稿恢复。

本机组合层必须保留原应用生命周期，先等待 Personal Agent 停止调度并清空会话/任务，再关闭数据库池；不能用自定义 lifespan 覆盖原 shutdown hook，参照[FastAPI 生命周期说明](https://fastapi.tiangolo.com/advanced/events/)。退出后不再保留后台工作，不把已暂停委托重新启用。原生组合的关闭顺序、后台跨对话提问、暂停后普通事实登记及刷新回读均有隔离实例回归。

旧版实例需先创建并验证原修订 checkpoint，再显式迁移；保留原事实、任务、聊天、文档及回执摘要。升级失败保持旧版本或明确拒绝启动，不自动删表降级。停用调度和暂停委托可停止新主动运行，保留历史及原手动聊天。具体可用性以测试及 PR CI 证据为准，本文件不预填“已完成”。

## 实现边界与演练方式

双人材料收集是后续独立的[窄协作切片](two-teacher-material-summary.md)，不替换本内置任务或可选偏好。收到的同事文档保留署名、源版本和实际正文，通过独立来源绑定的候选准备小结；远端文字不是老师指令或本地事实。接收与材料投递共用本服务的调度/停止生命周期，仍不自动保存。D4最新目标0034，0033→0034只增协作专表及封闭命令约束，先验证完整checkpoint并逐表比较旧值；下文0032→0033为内置任务的既有历史，不改写其证据。

已有普通事实或任务时，打开原应用即登记当前有效会话的检查；不必说“持续整理本班”。系统准备的小结通过原聊天列表和首页“需要我处理”进入，默认不提问班会主题；核对候选、确认保存、文档回读沿原动线。说“以后用三条要点整理小结”准备可选偏好，“这次详细一点”不改长期格式；“暂停整理班级小结”确认后停止，“恢复整理班级小结”可修订同一暂停偏好，没有暂停则不另建启用文档。普通聊天仍无需班级，自动准备只对当前有效班级/学期生效；不复活已归档聊天或接管碰巧同ID的人类聊天。无值得呈现的内置执行保留历史，但不新增空白聊天或待处理提示。

调度只在本机API和已登记有效会话可用时运行；Web用显式POST登记，8秒只读刷新结果，不抢焦点或清除未发送文字。没有新材料、无有效班级、默认模型未配置或偏好已暂停时不调用模型。内置与自定义小结合计每位用户24小时最多6次新主动运行，至少间隔1分钟；相同来源失败或未知结果不自动重复派发，原聊天可明确重试。普通事实与任务合计最多100条，超限拒绝生成，不冒充完整历史总结；调度/模型耗时不等于保证准点。触发频率和真实净减负仍是待验证假设，不以每次生成都成功或每条任务变化都值得打扰为前提。

老师答复作为小结中的有署名补充，不自动成为学生事实。当前仅学习明确的长期格式修订，不依据隐含偏好生成个人画像；没有通用目标规划、全天唤醒、通知推送、外部发信、自动安装 Skill、自动更新学校规则或任意记忆写入。

待答问题只是Context，不能覆盖当前意图。老师可先提出其他问题或办理其他事项，必要的政策检索等工具仍可用；无关聊天不消费小结问题。只有明确的小结材料答复/原重试才使用窄工具集合和强制草稿/待答约束，之后返回答复仍可继续原小结。

当前D4从0032显式升级到0033；新增表仅保存内置执行身份与来源，旧偏好、文档、聊天及全部业务表保持原值。升级事务失败保留原修订，可沿同一受控操作重试。停止自动准备优先确认暂停偏好；如必须回退二进制，先停止服务并保留升级后的完整checkpoint及新增数据，再恢复已实际核验的0032 checkpoint。旧备份不含后来新增内容，不能直接覆盖当前库或删表降级；新数据的保留/重放必须单独核验。

等待关系必须绑定实际的`ask_summary_question`调用与消息，不能把模型普通文字提问当作已持久等待。该工具复用SDK顺序屏障，先读当前事实/任务再提问；纯文字“已准备好”也不能代替真实文档候选。主动运行和已确认问题的答复都执行相同约束，模型拒绝使用契约时保留失败，不捏造问题状态。

持续小结的资料前置条件是本轮实际完成、未筛选且未截断的普通事实与任务读取。按学生、关键词得到的成功结果仍可服务普通定向查询，但不能证明全班没有其他材料，班级名称也不能作为事实正文的默认筛选词。提问缺项、准备小结和主动判断无新价值共用此检查；修正仍沿原Pydantic AI有限工具循环，不追加表单或放宽调用预算。资料数量超过原上限时拒绝冒充完整小结，不因此扩大事实权限或自动保存。

## 自定义班级目标的首个闭环

老师可在原对话委托一件有明确交付件的工作，例如“请持续跟进这个目标，核对回执名单后准备活动回执小结。”当前活跃班级学期可关联一份这样的目标委托，补充材料回到发起时的对话。老师指定小结标题与一项要核对的材料，确认后开始。普通内置小结与长期格式偏好照常工作。调整或暂停目标仍走同一预览确认。

执行沿用 Pydantic AI、APScheduler、授权聊天和业务回执。目标在现有文档表内以独立的固定结构、精确修订及真实确认回执绑定原对话。触发时读当前班务记录与任务。缺材料时只在原对话提出一条待答问题，直到这个问题之后有明确答复，例如“回执名单是……”。别的对话、较早发言、模型文本和含糊回复不能解除等待。补充原话以“老师补充”保留在交付件中，经原文档预览确认后保存。完成以该目标候选的持久保存回执为准，完成后停止推进。

重开应用后，现有授权会话重新登记检查，读取已确认目标、待答问题、当前资料和已保存回执。未进入模型的排队步骤使用原请求号。经确认已中断并转为未知的运行，以相同输入最多重新准备一次。突然断电时等原五分钟租约过期后才能接续。查询、提问和准备候选可续做，保存从不自动重放。明确失败按原对话的重试入口处理。未配置模型、暂停、归档或班级学期关闭时不派发，沿用调度配额和模型期限。

按 PA-01～08 与 PA-23～28 的工程证据核对确认前不执行、等待期间不空转、跨对话隔离、服务重启后恢复、陈旧预览拒绝、保存后停止及重复检查无第二份交付件。目标接入不改变冻结 R1 或正式验收状态。D4 仍为 0034，复用原表，无数据库迁移。本切片只覆盖有材料约束的小结交付。已有目标历史的备份应使用认识该委托格式的版本验证和恢复。回退时先确认暂停并保留新 checkpoint，避免用旧应用直接覆盖已有目标历史。

老师补充的必需材料不能因写入小结而成为已完成活动的证据。标准Markdown中，补充内容置于“已完成”区时拒绝候选并沿原SDK修正；使用既有markdown-it-py解析真实分区，包括加粗、嵌套标题，代码示例不作为事实段落。补充可置于独立“老师补充”区，原事实和任务状态不变。本轮完整任务读取同时保留不可变的标题/状态对，以原任务标题明确开头的条目（含“任务：”、加粗或引号）放在冲突的“已完成/进行中”分区时拒绝候选；较短标题不抢占较长任务名，同名而不同状态不能擅自消歧。普通事实句中碰巧包含短任务名不据此判定任务状态；多任务混合正文、改写及隐含推断不由此窄检查证明。这不是完整自然语言真实性或事实覆盖率判定，仍须原预览确认。

长期格式反馈可以省略原已确认的材料要求，也可以原样重复它；服务端从当前委托核实相同值，不要求老师重复确认已知信息。新增或改动的材料要求仍须出现于本轮原话，历史聊天、模型拼接引用和猜测不能替代。此修正只减少无意义的重新提问，仍须原委托修订预览与人工确认。

暂停/恢复的窄指令保护须检查本轮完整人类请求，不能只凭模型摘出的“恢复”子串丢弃其前面的否定；否定、假设和“这次/仅本次”不得产生长期暂停/恢复候选。既有明确长期偏好、实际源数据及人工确认继续决定后续行为。此检查不替代模型理解，也不声称覆盖全部自然语言歧义。

工程验收使用实际 Pydantic AI FunctionModel 工具循环、隔离 PostgreSQL、真实 HTTP 和原 Web。它证明程序链路，不代表供应商质量。`test_personal_summary_live.py` 仅在显式 `CLASSMATTER_PERSONAL_LIVE=approved-free-only` 时使用已有已激活免费模型，凭据仅经本机保护信封驻内存，不写报告或仓库；逐次失败和成功分别留本机报告，不自动开通付费。

工作区首页与主动小结不得以完整旧班级会话导出包可读为前置条件。原旧会话入口按需展开读取，失败局限于该区域并保留明确重试。当前D2/D3/D4在线旧会话校验已与完整导出分开：分批验证全部审计，只有本次有限会话快照所需的原始来源和完成凭据进入内部校验包；分类、回执、原结果与保护根校验保留。完整导出仍携带全部审计并执行原容量上限，不截断、删除或伪造空存档；现有会话/核心快照上限与原D1环境不变，不宣称无限历史容量。
