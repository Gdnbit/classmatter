# 工作区聊天持久化与对话办理实施单元

日期：2026-11-08。状态：本机核心链路及Gemini原桌面12轮合成真实调用小样本通过；持续可用性、真实教师使用效果和完整产品发布未完成。首轮全量回归、修复复验及真实调用分开保留，见实现台账，不代表一次性全绿或正式发布准入。

## 目标和范围

普通聊天归属已认证Owner/workspace，不要求存在class/term。班级信息仅在调用班级工具时通过QG获取；模型不能自选授权范围。复用Pydantic AI、现有模型配置、原聊天页面、QG/BCG/ISB和命令风险状态机。创建/编辑由AI准备typed候选，在对话内核对并确认，受信执行器调用原BCG；不注册approve/commit/SQL/DDL为工具。

先打通当前核心对象的纵向路径：班级/学期创建、班级名称修改、学生创建/更名、任务创建/修改、文档创建/修改。缺少必要信息时对话追问，不能编造日期、对象或资源版本。其余原型领域按实现台账检查，不把这些路径等同完整产品。

## 文件级顺序

1. `domain/workspace_chat.py`定义闭集交互、输入hash、状态/租约/候选规则；`0028_workspace_chat.py`和schema/role inventory新增显式D3存储，保留原D1/D2协议和表约束。新增表限定thread、turn、audit；候选仅保存封闭命令类型及校验hash，不是通用JSON文档库。
2. `application/workspace_chat.py`与`infrastructure/workspace_chat.py`复用BCG/QG事务及原生实例fence，保存后才运行模型，保存结果后才呈现成功。分页、归档、清除、取消、重启恢复、幂等和未知结果均有测试。旧退出格式不得漏掉新数据后声称完整；提供独立完整备份/恢复证据。
3. 现有SDK增加受控工作区工具和候选capture，模型只得到QG/候选能力；候选经原领域decoder、当前对象版本和原BCG预览/必要批准/提交。新增HTTP/typed schema与测试，不改变冻结R1定义或正式Gate状态。
4. 原`R1App`/`useDurableConversation`/`DurableConversation`逐步接线。聊天列表归工作区，业务视图仍从原QG读取。对话内候选卡替代表单前置，不另建工作台。
5. 受信operator与桌面接入D3：先验证备份与隔离恢复，再升级当前自有合成实例。保留开发免密码；不初始化/覆盖Owner，不使用生产数据或擅自启用付费Provider。

## 本机已启用模型的连续使用

仅默认 D3 本机开发入口可保存“此前测试并明确启用”的模型选择。`LocalModelActivation`存固定 kind、workspace、candidate/version、base_url 与显式 loopback proxy，既不保存密钥、消息或业务事实，也不承载任意设置。先经原模型 stage→BCG预览/批准/提交→真实工具检测→明确启用，才写本机记录；仅保存Key不会产生记录。标准非本机入口保持原进程级激活规则。

下次启动由私有父进程管道读取该记录并恢复已确认传输；显式operator参数优先，仍经过现有网络参数校验。控制器从QG核对同一candidate/version、密钥是否仍存在及端点是否被允许，才能使用原Pydantic AI适配。新进程的`test_passed`不会伪装为本次测试通过；配置变化标记stale并拒绝运行，不回退合成回答。停用模型将原子写入停用记录，跨重启保持停用。读取状态和启动不测试模型、不发送历史、不自动重跑任何轮次；实际发送才调用Provider。

当前`gemini-3.1-flash-lite`使用原Google SDK的MINIMAL思考设置；其他模型保持原默认值。Google单请求上限30秒、连通性双请求工具检测35秒，聊天整体仍为45秒，并保留请求数、Token、工具数及取消边界，无静默重试或自动付费切换。原SDK签名及后续工具协议不手写替代。此记录不进入业务Schema或跨机备份恢复的模型激活证明，恢复出的实例仍需独立明确启用。

## 验收条件

### 原界面布局与模型选择（2026-11-08）

聊天展示只使用用户需要的信息：不显示数据库、授权范围、临时上下文、Token及运行追踪说明。回答底部提供实际生成耗时和“复制回答”，只复制回答正文，成功与失败均给出简短反馈；没有耗时记录时不编造数字。运行指标仍保留在原存储/内部诊断中，移除展示不改变持久化、取消、候选确认和历史恢复。原刷新/归档/清除操作继续可用，不要求用户理解实现方式。

桌面复制使用标准Clipboard `writeText`；原一律拒绝的会话权限仅为当前应用窗口、同源主页面放行`clipboard-sanitized-write`，不开放剪贴板读取、子框架、其他来源或通用IPC。浏览器覆盖正文复制与拒绝反馈；Windows原生验收核对系统剪贴板与正文一致（仅规范化平台换行，不打印内容），同时保持聊天重启恢复检查。

左侧只保留对话、总览、学生、工作四个主入口；数据与内容、视图由“更多功能”展开。新对话归聊天列表；事件区直接复用当前合法班级的QG未完成任务投影，显示未开始、进行中和等待状态，不另建事件表或编造责任候选。无班级时仍可聊天。班级切换及兼容人工维护入口收进底部工作区旁的设置浮层；设置沿用原内容和命令，不形成另一套工作台或强制前置表单。

第一轮输入保存/运行时，整个欢迎区（标题、注意力栏、快捷操作）向上淡出并收起。恢复已有会话同样收起；新对话恢复欢迎区。尊重减少动态效果设置；隐藏内容不可聚焦。输入框保持挂载、固定底部，设置与模型菜单不清空未发送草稿。用户消息按内容宽度靠右，助手消息靠左，均不显示头像；主区域横向留白缩至约34px，长文本换行，不靠横向滚动换取宽度。

右下角模型选择器展示当前实际启用配置。同服务商切换通过`stage-model`核对当前candidate/version/endpoint，从本机密钥存储复用原Key，生成原`model_configuration.save`候选；仍走原BCG预览、明确批准、提交。保存切换不等于启用，需显式测试并启用，失败/未知不得静默回退或重跑。运行中禁切换。最近成功启用的模型ID仅为本地显示偏好，最多8条、按workspace/协议/地址分隔，不能提供权限、密钥或业务事实。未配置/不可用模型不冒充已连接；不同服务商仍通过原模型管理界面配置，不承诺任意模型兼容或免费。

不新增业务Schema、迁移、Agent写工具、正式Requirement/Eval/Task/Gate语义。本次是现有聊天开发单元的界面及模型配置适配；正式R1范围和准入不变。验收包括原页面创建/编辑回读、草稿保留、四入口/更多/设置、欢迎区高度归零、无头像/横向偏移、模型切换原BCG和测试启用、旧版本/运行中拒绝、刷新不重跑及零外部请求的合成浏览器回归。

- 无班级可新建/发送/刷新/重启恢复聊天；历史读取、重连不调用模型。
- 同一请求双发/响应丢失不重复模型调用或业务提交；失败/超时/取消/审计失败不能呈现成功结果。
- 普通话题无班级读取；使用班级工具时才绑定当前合法class/term，跨Owner/workspace、归档对象、版本冲突均拒绝。
- 对话补齐必要信息并展示候选，确认后创建/编辑可在原学生/工作/文档页面及刷新后看到；确认前零业务变更。
- 新聊天数据有分页、限制、归档/清除、完整备份和隔离恢复验证；恢复不激活模型或自动重放未知请求。
- 类型检查、契约漂移、相关PG/HTTP/浏览器/故障测试、原范围回归、public_guard及固定secret scan通过。真实Provider质量与可用性证据单独记录，合成测试不替代它。

## 风险和回滚

新增profile只接受显式受信迁移，不能悄悄改变D1/D2 head。候选可能错误或过时，因此业务写入仍以领域校验、CAS和必要确认授权。迁移回滚采用升级前完整备份到隔离目录验证后显式恢复，不DROP数据或改Alembic历史。保留旧代码/实例描述符和备份；任何回滚丢失升级后数据的风险必须明确呈现。

当前仍只获合成开发授权；最终使用检查必须列出真实模型、真实教师验证、发布准入、尚未接通原型领域等剩余条件，不能将本计划写成已完成。

## 已实现的工程链与边界（2026-11-08）

命名口径：`workspace-chat-d3`是本轮显式0028存储/启动profile名称，不等于早期数据库提案中“D3可靠变更流”规划已完成，也不代表工作专题、实时订阅或整个后续阶段交付。原D0验收页保留其阶段编号和历史结论，本轮能力按本文件与最新实现台账单独核对。

数据流：原消息框 → workspace-chat固定DTO → ISB → BCG保存输入和请求UUID → 显式claim → 原Pydantic AI → QG读取/封闭候选 → BCG保存回答与审计 → 前端回读。候选确认走原`commands/preview|approve|commit`，没有另建业务写引擎。文档通过原命令入口提交时，其回执同样按document_id与版本绑定，不能把已保存文档误报为未知后重复新建。

实现地图：

| 关注点 | 代码 |
| --- | --- |
| 固定状态/输入hash/候选验证 | `backend/src/class_os/domain/workspace_chat.py` |
| ISB/BCG/QG及固定SQL | `backend/src/class_os/application/workspace_chat.py`、`infrastructure/workspace_chat.py` |

| 原生升级/启动/备份 | `workspace_upgrade.py`、`workspace_local_runtime.py`、原`operator_backup.py`与桌面宿主 |

普通聊天的模型上下文不会自动关联班级。对话式操作覆盖班级创建/改名、学期元数据修改、学生创建/更名、任务创建/标题及开放状态修改、文档创建/完整修订或追加。完整替换文档前必须读取旧正文；追加保留旧正文。缺信息时追问；同名学生/任务/文档拒绝猜选。多候选不批量执行，每轮至多一项；不推断责任、期限或正式学生事实。

旧D1班级历史保留原存储与来源校验，由原侧栏列出并按原class/term深链读取；它不改变新工作区聊天的范围。列表只是界面元数据查询，不是给普通聊天模型预取班级事实；切换班级/身份先清除旧列表再读新范围，首次启用的列表加载也须通过epoch时序回归。旧会话点“新对话”回到工作区新会话，不能将新输入误续到旧会话。

全新开发实例通过受信operator的`prepare-chat --profile conversation-d1 --pg-root ...`显式准备：仅不存在的目录可复用原D1初始化/开发身份和同一备份升级链；已有目录拒绝覆盖。它不是桌面启动的隐式初始化，也不是Agent工具。现有实例仍走显式`upgrade-chat`，正常启动只检查现有D3状态。

分页每页20轮、50会话；每会话最多10000轮；每轮输入2000字、回答4000字。SDK使用最近最多6轮/8000字文本，不恢复历史工具或批准。模型调用最多4次、工具3次，总Token上限16000；部署超时45秒。供应商Token/延迟是可观察记录，不是费用证明。没有自动后台续跑、自动压缩长期记忆或通用Workflow。

输入保存结果未知时按原UUID/原文本恢复，不换键重发；模型启动由人工显式继续。取消版本化保存，迟到输出不采纳；重启看到运行中时可取消，不因刷新重跑。归档保留可查历史；清除聊天正文/候选不删除已提交业务数据，也不自动抹除旧备份。D3完整本机checkpoint和隔离恢复包含三张新表；跨机迁移、带新表的完整世界退出/重新准入仍未实现，旧部分退出明确拒绝。
