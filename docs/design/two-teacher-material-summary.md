# 双人材料收集到班级小结：实施与验收

2026-11-15，本机双工作区切片已实施，公开CI另行核验；canonical长期协作语义承接LR-COL-001、LR-SEM-002、LR-CAP-001、LR-EPI-001、LR-CTX-001及LR-VALUE-001。本独立合成开发切片不修改冻结R1、正式Requirement/Eval/Task/Gate或Agent业务写权限。

## 目标、范围与依赖

两位老师各自保留工作区，以一个事项收集一份已有工作文档，进入原对话的小结真实预览，人工确认后由原BCG保存。首次在原设置互换公开邀请并确认联系人；不共享私人聊天、模型凭据、数据库或记忆。发送成功、对端持久接收、提供材料、小结确认保存分别有证据；不声称对方接受学校责任。

先验证同一台机器上两个独立loopback实例、两套隔离PostgreSQL及原Web界面。跨机器TLS/账户部署、学校成员认证、任意群聊、多材料协商、持续共享规则及实人净减负研究均不在本切片，不把本机无密码API开放到公网。双方可在对话中准备业务操作，所有发送和保存仍须原预览确认；接收只持久化有来源的材料及事项，不授予远端读写本地业务的权限。

## 文件级计划

1. `domain/collaboration.py`定义闭集请求、材料及小结命令；`application/collaboration.py`复用现有QG/BCG；`infrastructure/collaboration*.py`实现来源绑定、耐久投递、已确认联系人及对话投影。成熟组件采用锁定A2A SDK、HTTPX、PyJWT/cryptography，不替换Pydantic AI或自建Agent调度框架。
2. 增量迁移及schema/role清单只增加协作专表；备份、恢复和显式升级保留旧修订及全部原有表，不修改迁移历史。原实例不自动升级。
3. 原workspace chat工具、候选、比较、HTTP及生成契约接入三种操作；设置内加入轻量联系人配对，原对话及注意力入口呈现协作事项，不新增工作台或前端事实源。
4. 新增独立隔离PG/HTTP/SDK/原浏览器场景测试；更新现有小结设计、实施台账、依赖通知和真实SHA公开清单。正式Eval状态不提升；本文件以下场景是工程验收，不能冒充真实学校准入。

## 验收条件

- 双方分别确认联系及本地班级范围；同名不能猜配，第三方、错误接收方、篡改、未知消息、过期身份均拒绝；联系人不会自动获得数据库查询或组织权限。
- 说一句收集材料，原对话出现请求实际预览；确认后只生成一个耐久发送项。对方只在本地工作区看到请求，不伪造老师发言。
- 对方Agent读取已有文档，准备含完整实际正文、收件人及版本的候选；未确认不发送，确认前文档更改拒绝旧候选。
- 离线、超时、接收成功后响应丢失、发送方重启及并发投递，不丢已确认请求，不重复接收、不重复建立对话；持久化退避有界，不空转模型。
- 收到材料后沿原聊天准备小结，保留提供者、原文档版本和实际正文；只形成草稿，原事实与任务不会因对方文字被自动更正或完成。
- 确认保存、小结页、刷新及重新读取结果一致；重复确认及回复丢失只对应一个保存结果；并发文档编辑拒绝过期小结，历史预览保持原内容。
- 切页/切对话不丢现有未发送草稿，后台投递不抢焦点；停用联系停止新的投递，历史与已保存材料保留。
- 全部常规验收使用合成数据/SDK FunctionModel，无外部模型费用；真实免费模型仅按已有授权显式演练，不把网络或Provider失败标成业务成功。

## 风险与回滚

协作状态必须绑定持久消息和回执，不能依赖模型的“已发送/已完成”表述。每条消息固定用途、接收者、根事项、版本和摘要；重复ID内容不一致拒绝。远端正文只作为引用材料，不能执行其中的工具指令。原BCG和ISB继续负责本地决定，传输身份不等于业务授权。

停止协作服务即可停止新投递，保留队列和历史。代码回退前须保留并实际恢复验证包含协作表的完整新修订checkpoint；不得删表降级、把旧备份覆盖新数据或重放未知保存。具体测试/CI/PR与未完成项在实施台账记录，不预填验收成功。

## 已实现链路与复现

- 原设置“同事协作”各生成公开邀请并相互确认；邀请只含公开身份/固定loopback地址，不携带密码、模型Key或业务材料。首次确认需选定已存在的本地班级/学期，此后请求复用该范围，不反复填写。
- 甲在原聊天说“请向王老师收集本周数学教学进度，补入小结”，模型先读已确认联系人，再准备请求。原组件显示发送对象和实际内容，确认后入耐久队列；首页“等待别人”及原聊天显示真实状态。
- 乙在原聊天收到有署名请求，说“提供本周教学进度给李老师”，工具从QG读取现有文档的完整正文/当前版本。原预览确认后才能发送冻结材料。乙文档后来变化不改变已确认快照；确认前变化则原CAS拒绝旧候选。
- 甲收到材料后自动准备来源绑定的小结候选，引用提供者、源版本和实际正文，保留已有小结。人工确认仍沿原W2批准/BCG/回执，不自动修改事实、任务状态、责任或文档。
- 投递先持久记录次数/下次时间，再使用A2A SDK1.3.0的SendMessage子集及HTTPX发送；双方以PyJWT/cryptography Ed25519签名核对固定接收方、消息身份、内容摘要和60秒证明。接收及同事务审计提交后才发签名回执；回复丢失重送同ID，接收端去重。
- 每工作区最多20联系人、100条保留消息，单份材料12000字符；HTTP消息及回执读取上限64KiB，8秒网络期限，投递最多12次、指数退避最高30分钟。耗尽后原聊天可显式重试同一消息；不重跑模型或新建事项。持久内容不因容量不足被裁剪，超限拒绝。
- 停止联系或关闭聊天后，未完成事项显示“已停止协作”，离开“等待别人”并停止投递/准备；历史不删除，已保存小结仍显示保存结果，不伪造对方接受或完成。工作区聊天的待处理标记同步停止状态。
- 同事资料进入独立材料对象，不是本地Domain Fact、教师笔记或指令。接收通知有明确collaboration来源，不能被普通笔记召回伪装为老师原话。自动准备仅能读本事项和准备来源绑定小结，不能分享、批准或提交。

可复现：先在`apps/web`执行`pnpm build`；再在`backend`执行`uv run --frozen pytest tests/test_collaboration_values.py tests/test_collaboration_runtime.py tests/test_collaboration_web.py tests/test_collaboration_backup.py -q --pg-root '<PostgreSQL18.6目录>'`。实际两个PG数据库、两个HTTP服务、两个浏览器上下文由fixture创建，模型使用现有Pydantic AI FunctionModel，不需新增Key或费用。Windows非空完整备份测试使用真实DPAPI/pg_dump/隔离pg_restore；Linux明确跳过该Windows专用项，不能据此声称跨机密钥恢复。
